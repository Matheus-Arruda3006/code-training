# Conciliação de lançamentos por conta

Linguagem: TypeScript

## Pré-requisitos
JavaScript, interfaces, generics e narrowing.

## 1. Problema
Consolidar diferenças entre valores esperados e recebidos. Saída: pares conta, diferença apenas para contas divergentes, em ordem de ID.

## 2. Decisão de arquitetura
Agrupar antes de comparar evita sinalizar uma cobrança parcialmente liquidada quando seus recebimentos se compensam. Tipos explícitos no núcleo, strict no compilador e validação em runtime. Uma anotação TypeScript não valida JSON recebido.

## Contrato de dados

TSV com cabeçalho e até 200 registros. Cada campo é um inteiro dentro dos limites inclusivos. Na API .NET, envie as linhas como arrays em data.

| Índice | Campo | Mínimo | Máximo |
|---|---|---|---|
| 0 | account | 0 | 99 |
| 1 | expected | 0 | 10000 |
| 2 | settled | 0 | 10000 |

## Roteiro guiado

1. Defina o contrato: Consolidar diferenças entre valores esperados e recebidos. Saída: pares conta, diferença apenas para contas divergentes, em ordem de ID.

2. Crie os arquivos de domínio e leia a decisão: Agrupar antes de comparar evita sinalizar uma cobrança parcialmente liquidada quando seus recebimentos se compensam.

3. Implemente o adaptador da linguagem: Tipos explícitos no núcleo, strict no compilador e validação em runtime. Uma anotação TypeScript não valida JSON recebido.

4. Execute os testes antes de usar input.tsv. Os valores esperados são fixos e independentes do retorno calculado.

5. Faça uma extensão autoral: Acrescente um identificador de transação e detecte duplicidades antes de conciliar.

## 4. Execute na pasta do projeto
```sh
npm install

node dist/main.js input.tsv
```


## 5. Resultado esperado
```
[2,30]
```

## 6. Critérios de aceite
- Caso 1: entrada [[1,100,70],[1,30,60],[2,50,20]] deve produzir [2,30].
- Caso 2: entrada [[3,10,20]] deve produzir [3,-10].
- Caso 3: entrada [] deve produzir [].
- Rejeitar colunas incorretas, valores fora dos limites e mais de 200 registros.
